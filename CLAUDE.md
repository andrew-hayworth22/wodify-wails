# Project Architecture

Wodify desktop client built with **Wails v2** (Go backend + webview frontend). Go module: `github.com/andrew-hayworth22/wodify-wails`. The Go side talks to the Wodify API via `github.com/andrew-hayworth22/wodify-go`; the frontend is a **SvelteKit 3 SPA** (Svelte 5, TypeScript 6, Tailwind CSS v4, Vite 8).

## Layout

```

wails.json                    Wails project config (app name "Wodify", output binary "wodify")
internal/
  app/
    app.go                    App struct (ctx, config, session), Startup(), EventAuthExpired, Greet() (template leftover)
    config.go                 Bound methods: GetConfig, SetConfig, SaveConfig, HasAPIToken, SetAPIToken, SignOut
  config/
    config.go                 Config struct (base_url, timeout, theme), Theme* constants, Read/Write of the JSON file
  session/
    session.go                Session: token + wodify.Client behind a mutex; New, SetToken, SetClientOptions, Clear
    token.go                  OS keyring get/set/delete for the API token
    call.go                   Call[T]: runs an API call; a 401 clears the session and fires OnUnauthorized
    errors.go                 Error type (unauthorized, validation, …), toError mapping, FormatError
frontend/
  vite.config.ts              Tailwind + SvelteKit plugins; SvelteKit config (adapter, preprocess) lives here
  tsconfig.json               Extends `$app/tsconfig` (required by SvelteKit 3)
  package.json                `imports` field defines the `#lib` alias → src/lib
  src/
    app.html                  HTML shell (<html> classes for light/dark background)
    style.css                 Tailwind import + class-based `dark` variant
    assets/images/appicon.png App logo (splash + welcome screen)
    components/               Reusable UI components (Button, Input)
    routes/
      +layout.ts              ssr = false (no auth logic)
      +layout.svelte          Loads config store behind a splash, shows the window, toggles `dark` class on <html>
      welcome/
        +page.ts              Reverse guard: has API token → redirect to /
        +page.svelte          Logo + API key entry; calls SetAPIToken then goto('/')
      (app)/                  Route group for authenticated pages (no URL segment)
        +layout.ts            Auth guard: no API token → redirect to /welcome; depends(AUTH_DEP)
        +layout.svelte        App shell (placeholder header/nav); on AUTH_EXPIRED_EVENT calls invalidate(AUTH_DEP)
        +page.svelte          Main screen at "/" (placeholder)

    lib/

  wailsjs/                    GENERATED by Wails — do not edit by hand
    go/app/App.{js,d.ts}      JS bindings for exported methods on *app.App
```

## Backend (Go)

- **`main.go`** creates `app.New()`, passes `a.Startup` as `OnStartup`, and lists `a` in `Bind` — every exported method on `*app.App` becomes callable from the frontend. The window uses `StartHidden: true`; the frontend calls `WindowShow()` once its first frame is themed (see Frontend).
- **`internal/app`** is the binding layer. `App` holds the Wails `context.Context`, the loaded `*config.Config`, and the `*session.Session`. Keep bound methods thin; put logic in other `internal/` packages.
  - `Startup` schedules a fallback `WindowShow` after `windowShowFallback` (3s) in case the frontend never shows the window, reads config, then creates the session from `BaseURL`/`Timeout` with an `OnUnauthorized` callback that emits `EventAuthExpired` to the frontend.
  - `HasAPIToken()` reports whether the session has a token. `SetAPIToken(token)` delegates to `Session.SetToken`. `SignOut()` calls `Session.Clear`.
  - `SetConfig(cfg)` pushes the new `BaseURL`/`Timeout` into the session (rebuilding the client), then replaces the in-memory config. `SaveConfig()` writes it to disk.
- **`internal/config`** owns non-secret settings only:
  - `base_url`, `timeout` (Go `time.Duration`, so nanoseconds in JSON/JS), and `theme` are JSON at `os.UserConfigDir()/Wodify/config.json` (macOS: `~/Library/Application Support/Wodify/config.json`).
  - `defaultConfig()` is used when the file doesn't exist: `BaseURL` `https://devapi.wodify.com/v1`, `Theme` `ThemeSystem`.
  - `Read()` loads the file (or defaults); `Write()` saves it.
- **`internal/session`** owns the API token and client:
  - The token lives only in the OS keyring (service `wodify`, account `session-token`) via `zalando/go-keyring`. A missing entry means no token on read and is not an error on delete. The token never reaches the frontend.
  - `New` loads the token and builds a `wodify.Client` if one exists (`BaseURL`, plus `Timeout` when > 0).
  - `SetToken` verifies the token with a cheap read-only call (`Utils.ListGenders`, 1 row — the API has no "validate token" endpoint), then saves it to the keyring and swaps in the new client. `Clear` removes it from memory and the keyring.
  - Make API calls through `Call[T](ctx, s, fn)`. It returns errors as `*session.Error`, and on a 401 it clears the session and fires `OnUnauthorized`.

## Frontend (SvelteKit SPA)

- **SPA mode**: `@sveltejs/adapter-static` with `fallback: 'index.html'`, output to `dist/` (what `main.go` embeds), and `ssr = false` in `routes/+layout.ts`. There is no server — everything runs in the Wails webview.
- **Routing / auth guard**:
  - Authenticated pages live in the `(app)` route group. Its `+layout.ts` calls `HasAPIToken()` and redirects to `/welcome` without a token, and its `+layout.svelte` is the shared app shell.
  - Put new authenticated pages under `(app)/` (e.g. `(app)/clients/+page.svelte` → `/clients`) and add links in the shell's `<nav>`.
  - `/welcome` sits outside the group, so it gets no shell. Its `+page.ts` redirects to `/` when a token already exists.
  - The `(app)` guard doesn't read `url`, so it runs when entering the group, not on every navigation within it. After the token changes (e.g. cleared on an unauthorized error), call `invalidate(AUTH_DEP)` (from `#lib/auth.ts`) to re-run it. The shell already does this when Go emits `AUTH_EXPIRED_EVENT`. Use these constants instead of string literals; the event name must match `EventAuthExpired` in `internal/app/app.go`.
  - Only one route may resolve to `/`, so don't add a root `routes/+page.svelte` alongside `(app)/+page.svelte`.
- **SvelteKit 3 specifics**:
  - No `svelte.config.js`; config is passed to `sveltekit({...})` in `vite.config.ts`, with no `kit:` wrapper.
  - `$lib` is replaced by `#lib` (Node subpath `imports` in `package.json`). Include the file extension, e.g. `#lib/stores/config.ts`, so TypeScript resolves it.
  - `node_modules/$app` is generated by SvelteKit and is expected.
- Svelte 5 runes (`$state`, `$props`, `$effect`) are used alongside `svelte/store` stores.
- Go calls go through the generated imports in `frontend/wailsjs/go/...`, imported by relative path. `lib/stores/config.ts` shows the store pattern: `subscribe` plus async methods that call bindings and update state.
- Theme: `config.Theme` is `"system"`, `"light"`, or `"dark"` (empty is treated as `"system"`, the default). `+layout.svelte` toggles the `dark` class on `document.documentElement` when the theme is `"dark"`, or when it's system and the `prefers-color-scheme: dark` media query matches (it listens for OS changes live); `style.css` defines `@variant dark (&:where(.dark, .dark *))` so Tailwind `dark:` utilities follow that class.
- Startup: the root `+layout.svelte` renders a splash (logo + spinner) until the config has loaded and at least `SPLASH_MIN_MS` has passed, then renders the routes. It calls `WindowShow()` right after the splash first renders. Pages can assume `$config` is loaded.
- Reusable UI components go in `src/components/` (e.g. `Button.svelte` with `primary`/`secondary` variants, `Input.svelte` with bindable `value`), imported by relative path. Extract shared markup there instead of duplicating Tailwind classes across pages.
- Pages call Go bindings, so they only work inside Wails (`wails dev`), not in a plain browser tab on the Vite server.

## Go ↔ JS bindings

- After adding/changing exported methods on `*app.App` or structs they return, regenerate bindings with `wails generate module` (or run `wails dev`, which regenerates them).
- JSON tags on Go structs determine field names in `models.ts` (snake_case here, e.g. `base_url`).
- Bound methods returning `error` reject the JS promise with the error message string.

## Commands

- `wails dev` — run with hot reload
- `wails build` — production build to `build/bin/`
- `cd frontend && npm run check` — `svelte-kit sync` + svelte-check type checking
- `cd frontend && npm run build` — build the SPA into `frontend/dist`
- `go build ./... && go vet ./...` — backend checks (no tests exist yet)

## Version constraints

- TypeScript is pinned to 6.x: SvelteKit 3 and svelte-check don't support TypeScript 7 yet.
