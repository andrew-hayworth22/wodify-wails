# Project Architecture

Wodify desktop client built with **Wails v2** (Go backend + webview frontend). Go module: `github.com/andrew-hayworth22/wodify-wails`. The Go side talks to the Wodify API via `github.com/andrew-hayworth22/wodify-go`; the frontend is a **SvelteKit 3 SPA** (Svelte 5, TypeScript 6, Tailwind CSS v4, Vite 8).

## Layout

```
main.go                       Wails entrypoint: window options, embeds frontend/dist, binds *app.App
wails.json                    Wails project config (app name "Wodify", output binary "wodify")
internal/
  app/
    app.go                    App struct (ctx, config, wodify client), Startup(), newClient(), Greet() (template leftover)
    config.go                 Bound methods: GetConfig, SetConfig, SaveConfig, HasAPIToken, SetAPIToken
  config/
    config.go                 Config struct + load/save (JSON file + OS keyring), SetToken
frontend/
  vite.config.ts              Tailwind + SvelteKit plugins; SvelteKit config (adapter, preprocess) lives here
  tsconfig.json               Extends `$app/tsconfig` (required by SvelteKit 3)
  package.json                `imports` field defines the `#lib` alias → src/lib
  src/
    app.html                  HTML shell (<html> classes for light/dark background)
    style.css                 Tailwind import + class-based `dark` variant
    routes/
      +layout.ts              ssr = false (no auth logic)
      +layout.svelte          Imports style.css, loads config store, toggles `dark` class on <html>
      welcome/
        +page.ts              Reverse guard: has API token → redirect to /
        +page.svelte          API key entry; calls SetAPIToken then goto('/')
      (app)/                  Route group for authenticated pages (no URL segment)
        +layout.ts            Auth guard: no API token → redirect to /welcome; depends('app:auth')
        +layout.svelte        App shell (placeholder header/nav) wrapping all authenticated pages
        +page.svelte          Main screen at "/" (placeholder)
    lib/
      stores/config.ts        Svelte writable store wrapping the Go config bindings
  wailsjs/                    GENERATED by Wails — do not edit by hand
    go/app/App.{js,d.ts}      JS bindings for exported methods on *app.App
    go/models.ts              TS classes generated from Go structs (e.g. config.Config)
    runtime/                  Wails runtime JS API
build/                        Platform build assets (icons, darwin/windows manifests); build/bin is output
```

## Backend (Go)

- **`main.go`** creates `app.New()`, passes `a.Startup` as `OnStartup`, and lists `a` in `Bind` — every exported method on `*app.App` becomes callable from the frontend.
- **`internal/app`** is the binding layer. `App` holds the Wails `context.Context`, the loaded `*config.Config`, and the `*wodify.Client` (`wc`). Keep bound methods thin; put logic in other `internal/` packages.
  - `Startup` reads config and, if a token exists, builds `wc` via `newClient` (API key, `BaseURL`, and `Timeout` when > 0).
  - `HasAPIToken()` reports whether a token is loaded.
  - `SetAPIToken(token)` builds a client, verifies the token with a cheap read-only call (`Utils.ListGenders`, 1 row — the API has no "validate token" endpoint), then saves it to the keyring and swaps in the new client.
  - `SetConfig` preserves the current `APIToken`, since the token never reaches the frontend.
- **`internal/config`** owns persistence:
  - Non-secret settings (`base_url`, `timeout`, `dark_mode`) are JSON at `os.UserConfigDir()/Wodify/config.json` (macOS: `~/Library/Application Support/Wodify/config.json`).
  - `defaultConfig()` is used when the file doesn't exist; default `BaseURL` is `https://devapi.wodify.com/v1`.
  - `APIToken` is tagged `json:"-"`; it lives only in the OS keyring (service `wodify`, account `api-token`) via `zalando/go-keyring`. A missing keyring entry means an empty token, not an error.
  - `Read()` loads the file (or defaults) then the token. `Write()` saves only the file; `SetToken()` saves only the token.

## Frontend (SvelteKit SPA)

- **SPA mode**: `@sveltejs/adapter-static` with `fallback: 'index.html'`, output to `dist/` (what `main.go` embeds), and `ssr = false` in `routes/+layout.ts`. There is no server — everything runs in the Wails webview.
- **Routing / auth guard**:
  - Authenticated pages live in the `(app)` route group. Its `+layout.ts` calls `HasAPIToken()` and redirects to `/welcome` without a token, and its `+layout.svelte` is the shared app shell.
  - Put new authenticated pages under `(app)/` (e.g. `(app)/clients/+page.svelte` → `/clients`) and add links in the shell's `<nav>`.
  - `/welcome` sits outside the group, so it gets no shell. Its `+page.ts` redirects to `/` when a token already exists.
  - The `(app)` guard doesn't read `url`, so it runs when entering the group, not on every navigation within it. After the token changes (e.g. cleared on an unauthorized error), call `invalidate('app:auth')` to re-run it.
  - Only one route may resolve to `/`, so don't add a root `routes/+page.svelte` alongside `(app)/+page.svelte`.
- **SvelteKit 3 specifics**:
  - No `svelte.config.js`; config is passed to `sveltekit({...})` in `vite.config.ts`, with no `kit:` wrapper.
  - `$lib` is replaced by `#lib` (Node subpath `imports` in `package.json`). Include the file extension, e.g. `#lib/stores/config.ts`, so TypeScript resolves it.
  - `node_modules/$app` is generated by SvelteKit and is expected.
- Svelte 5 runes (`$state`, `$props`, `$effect`) are used alongside `svelte/store` stores.
- Go calls go through the generated imports in `frontend/wailsjs/go/...`, imported by relative path. `lib/stores/config.ts` shows the store pattern: `subscribe` plus async methods that call bindings and update state.
- Dark mode: `+layout.svelte` toggles the `dark` class on `document.documentElement` from `$config.dark_mode`; `style.css` defines `@variant dark (&:where(.dark, .dark *))` so Tailwind `dark:` utilities follow that class.
- Pages call Go bindings, so they only work inside Wails (`wails dev`), not in a plain browser tab on the Vite server.

## Go ↔ JS bindings

- After adding/changing exported methods on `*app.App` or structs they return, regenerate bindings with `wails generate module` (or run `wails dev`, which regenerates them).
- JSON tags on Go structs determine field names in `models.ts` (snake_case here, e.g. `dark_mode`).
- Bound methods returning `error` reject the JS promise with the error message string.

## Commands

- `wails dev` — run with hot reload
- `wails build` — production build to `build/bin/`
- `cd frontend && npm run check` — `svelte-kit sync` + svelte-check type checking
- `cd frontend && npm run build` — build the SPA into `frontend/dist`
- `go build ./... && go vet ./...` — backend checks (no tests exist yet)

## Version constraints

- TypeScript is pinned to 6.x: SvelteKit 3 and svelte-check don't support TypeScript 7 yet.
